Why only these nine. Every metric sits on an event or activity log (TS Events, Viz Load Times, Job Performance). Those sources retain real history, so each metric trends honestly and compares period over period the day you turn Pulse on. Current-state snapshot sources (licensing, storage, subscriptions) full-refresh daily and keep no history, so they are held for a later version and listed at the bottom.

Breakdowns are set per metric. Each metric carries only the dimensions that return real values for it, favoring low and medium cardinality fields so Pulse top-contributor insights stay clean. A dimension the metric already filters on is left off.

Held for a later version

Cut for data-shape reasons, not lack of value. These sit on current-state snapshot sources with no history to trend, or carry survivorship bias on a creation-date cohort. Better served as point-in-time readouts in the Admin Insights views, or in a later tier built on a purpose-made fact source.

  • Data Source Connections (TS Events) — narrower governed-data signal, second-tier for the adoption story
  • New Users, Content Growth — cohort trends with survivorship bias
  • New Subscriptions & Metric Follows, Subscriptions Delivered — Subscriptions shape can't count delivery over time
  • Occupied Licenses, Remaining Licenses, Average Days Since Last Login, Site Storage Used — snapshot state, no source history

Advanced tier (needs calculated thresholds or ratios): Slow Loads (>10s), Inactive Users (>90 days), Stale Content (>90 days), License Utilization %, Refresh Success Rate %.

Planning artifact. Field names and filter values are validated against live data at build time.
